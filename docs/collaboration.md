# 协作与诊断协议

这份文件记录我们两个在 2026-11-23 ~ 11-24 这轮（ggufget 1.1.0 → 1.2.1）里达成的做事方式，
以及那条"日志里什么都没有"的教训。下次开新任务，把这份文件丢给我（`@ggufget/docs/collaboration.md`）就够。

## 一、这轮真正发生了什么（事实，不是猜测）

| 时间 | 事件 |
| --- | --- |
| 11-23 | 下载时 `mkdir C:\Users\you\.lmstudio\models\…: Access is denied.`，一个字节都没下 |
| 11-23 | 怀疑 360 主动防御 → 你卸载 360、加信任区，**仍然失败** |
| 11-24 | 我加 1.2.0 日志 + 写前预检，日志里能看到 `errno=5` 了，但找不到原因 |
| 11-24 | 我做对照实验：PowerShell 能建 `%APPDATA%\ggufget`，exe 不能 → 我错误地断定"exe 被按目录拦截" |
| 11-24 | 你发现 **真因：exe 没有以管理员身份运行**。提权后一切正常 |

**我的归因错在哪**：我用来对照的 PowerShell 是提权进程，我把 exe 复制到 `%TEMP%` 时它也跟着提权了。
"换一个目录"和"换一个权限级别"两个变量同时变了，我却把原因挂在"目录"上。
**教训：一次只改一个变量；动手改代码之前只做只读勘察。**

**代码本身没错的地方**：路径拼接、`lmstudio-ai` 布局、`os.MkdirAll` 都是对的——它忠实反映了操作系统的拒绝。
**代码确实不好的地方**（1.2.0/1.2.1 已修）：报错是原始的 `mkdir …: Access is denied.`、同一句错误打印两遍、
保存配置失败不进日志、没有下载前预检。

## 二、我们怎么合作（协议）

**你负责**：目标和约束——"我要什么"、"我不能接受什么"、"验收标准是什么"。
**我负责**：给出 2~3 个做法 + 各自代价 + 一个推荐，你只做选择。

具体到粒度：

- **小改**（一两个文件、不改默认行为）：直接做，做完说改了哪、怎么验证。
- **涉及结构、默认行为、命令契约、文档承诺**：先出一页方案，你点头再动手。
- **信息不足**：我说"缺什么"，而不是猜着做完再返工。
- **你只描述现象**（"点了没反应"、"这里报错"），不要给诊断；诊断是我的活，猜错了也是我的错。
- **我列假设时按可能性排序**，每条配一个"最便宜的判别实验"，做完汇报哪条被排除、为什么。

## 三、我需要你提供什么（照这个回我就行）

新任务开工时，如果能回答下面 6 行，我基本不会跑偏：

```
目标：            （一句话，想要什么结果）
现状：            （哪里不对 / 现在怎么用的，贴原话或截图）
不能接受的：      （比如"别改 hosts"、"别装东西"、"别动配置"）
环境：            （系统、版本、是不是管理员、装了什么安全软件）
验收标准：        （怎么算做好了，最好能一条命令或一张图证明）
时间/范围：        （今天就要 / 可以慢慢做；只改这一处 / 可以顺手重构）
```

不确定的就写"不知道"，我会先只读勘察再问。

## 四、诊断字段路线（下一步要做的日志增强，约半天）

（1.2.0 已经加入默认日志：启动环境、配置生效值、落盘路径、探测、错误链与 errno。下面这套“阶段流水”仍未做。）
现在的日志已经记了启动、配置、每个文件、probe、错误链与退出码；缺的是**第一次失败点之前的阶段流水**。
目标形态是阶段流水，一行一个阶段：

```
resolve   model_dir=C:\Users\you\.lmstudio\models source=lmstudio-settings
plan      repo=… file=… size=6935333888 layout=lmstudio dest=…
prepare   dir=… writable=false errno=5 chain=*fs.PathError: mkdir … <- syscall.Errno
          ^ 第一个失败点，后面的阶段不再出现
probe     url=… status=206 total=… ranges=true
transfer  conns=4 segs=4 resume=false
verify    sha256=… ok=true
commit    rename=… ok=true
```

配套改动：

1. `ggufget log --last`：直接打印最近一次运行的日志尾部，不用去找文件。
2. `--json` 模式下同一批事件以 NDJSON 输出，方便贴给我或写脚本。
3. 逐调用级别的细节（每次 write/read 的字节数）只在 `--log-level debug` 出现，默认不写。
4. 权限类失败一律带 `errno`、`PathError` 链和**当时用的完整路径**。

## 五、还没解决的问题（留给后面）

1. **为什么"非管理员"写不进 `.lmstudio\models`，而 LM Studio 自己能写？**
   可能：LM Studio 安装时给该目录加了 ACL / 它以自己的权限模型写入 / 360 对两者策略不同。
   验证方式：用非管理员窗口对比 `New-Item` 与 LM Studio 下载，看 ACL 与进程完整性级别。
   这件事决定了要不要在启动时提示"建议以管理员运行"。
2. **exe 应该固定放在哪**：建议 `D:\tools\ggufget\ggufget.exe` 并加入 PATH（现在散在 `dist` 里验证）。
3. **项目建 git 仓库**：现在所有历史都在对话里，一次误删就全没了。最高优先级、十分钟能做完。
   （已完成：2026-11-24 建库、推送，并发布 v1.2.1。）
4. **发版**：`.github/workflows/release.yml` 已经就绪，`git tag v1.2.1 && git push` 就会出六平台包；
   发之前记得把 `install/install.ps1` 的 `-Repo` 和 `install/install.sh` 的 `REPO` 从占位符改成真仓库。

## 六、不要重复的坑（本轮踩过的）

- 用 PowerShell 5.1 的 `Get-Content -Raw` / `Set-Content` 改 UTF-8 源码 → 中文全变乱码，一律用编辑工具。
- `less` / `more` 在 Windows 控制台输出 UTF-8 必乱码 → 用内置分页器。
- `time.Time` 加 `omitempty` 不起作用 → 用 `*time.Time`。
- 提权进程的子孙进程仍是提权的，别拿它当"普通用户"的对照组。
- 用户已在真机上验证过的结论（例如 LM Studio 的目录层级）直接当事实，不再反复求证。
