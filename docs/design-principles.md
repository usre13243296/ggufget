# 一个好用的命令行工具应该具备什么

写 `ggufget` 的时候我把"烦"当成了需求文档：凡是让我多敲一次命令、多查一次文档、或者让我怀疑"是不是卡住了"的地方，都是要修的东西。下面是这份清单，以及这个工具是怎么做的。

它不完整，也不神圣。但它来自真实的失败：一个把 `hosts` 写坏的晚上，和很多次看着 5 KB/s 进度条发呆的下午。

---

## 1. 一条命令就能装

安装是最容易被写坏的一步。用户还没决定要不要用你的工具，就先要读五行文档。

- 有**单文件可执行**，不依赖运行时。`ggufget` 用 `CGO_ENABLED=0` 静态编译，Windows / Linux / macOS × amd64 / arm64 各一个文件，扔进 PATH 就能跑。
- 有**安装脚本**，一条命令装好：下载 → 校验 SHA256 → 放进 PATH。Windows 用 PowerShell 5.1 也兼容，不需要管理员权限。
- **不需要先装包管理器**。不要求 Python、不要求 Node、不要求 `sudo`。

反例：`pip install` 再来一句 "requires Python >= 3.8 and a C compiler"。用户在这句话之前已经关掉了页面。

## 2. 默认值要对，配置要能看见

- 不写配置文件也能用，且默认值已经是大多数人想要的。
- 配置**可发现**：`ggufget config` 告诉你文件在哪、存不存在、每一项的生效值。不要让人猜"我改的到底是哪个文件"。
- 配置**不偷偷生成**：`--init` 明确写出，已存在就不覆盖。自动生成配置文件看起来贴心，实际会让"为什么我的设置没生效"变成一个哲学问题。
- 命令行 > 环境变量 > 配置文件 > 默认值，这个优先级要写进 `--help`，而不是只写在博客里。

## 3. 不要让人记住精确的字符串

最常见的失败不是网络错误，是"名字差一个字符"。

```
序号  文件                                    大小  量化
1     Qwen2.5-7B-Instruct-Q3_K_L.gguf        3.81 GiB  Q3_K_L
2     Qwen2.5-7B-Instruct-Q4_K_M.gguf        4.36 GiB  Q4_K_M
```

- 输出带**序号**，`-f 2` 比 `-f Qwen2.5-7B-Instruct-Q4_K_M.gguf` 好敲一万倍。
- 关键词**宽松匹配**：大小写不敏感、包含即可、去掉 `--file ` 前缀和引号、`\` 转 `/`。`q4_k_m` 就够了。
- 支持 **列表和区间**：`1,3`、`1-3`。
- **歧义不猜**：匹配到多个时列出候选然后失败。猜错一次的成本，远高于多敲一个数字。
- 输入 `--file 2` 这种"把选项抄进值里"的真实错误也要容错。

## 4. 进度必须可见，且不能骗人

- 有总大小、已下载、速度、ETA、当前连接数。没有这些，"卡住了"和"在慢慢下"看起来一模一样。
- **非 TTY 不乱写**：输出被重定向时，不刷 `\r` 动画，改成每 10 秒一行。日志文件不该长出 30000 个回车。
- **进度和结果分开**：进度走 stderr，结果走 stdout。这样 `ggufget list ... > files.txt` 拿到的只有数据，`2>/dev/null` 只留下进度。

## 5. 可中断，可续传，不留下坏文件

- 写临时文件（`.part`），**完成并校验通过之后才改名**。中途失败绝不留下一个"看起来完整"的坏模型。
- 续传要有**明确的依据**：单段按文件大小，多段按 journal 里每段已完成的位置。journal 里还存了总大小和 ETag —— 服务器上的文件变了，就从头再来，而不是把两个版本拼在一起。
- 中断时告诉用户**怎么继续**："已下载的部分保留在 X，重新运行可续传。" 而不是甩一个 `signal: interrupt`。

## 6. 失败要说人话，退出码要有契约

- 错误信息回答三个问题：**发生了什么、为什么、我该怎么办**。

  ```
  ✗ 所有镜像都没有取到 no-such/repo：
    modelscope 404 没有这个仓库
    hf-mirror  404 没有这个仓库
    hf         超时
  检查网络；或用 --provider 指定单个镜像、--proxy 指定代理后重试。
  ```

- **退出码是 API**：0 成功、2 参数错、3 网络、4 校验失败、5 磁盘满、6 不存在、7 权限、130 中断。脚本因此不用去 grep 英文错误信息。
- **不要把所有异常压成一行**。三个镜像都挂了，就列三行；只报第一个会让人去修错的镜像。
- 传输层的原始错误（`Get "https://...": dial tcp [2a03:...]:443: i/o timeout`）对用户没有价值，要折叠成 `超时`。

## 7. 帮助要分层，别把说明书塞进二进制

- 第一层 `--help` / `help`：命令总表，每个命令一行说明，加全局选项和退出码，一屏看完。
- 第二层 `ggufget help get`：单个命令的全部选项、示例、相关退出码。
- 第三层是**外置文档**（`MANUAL.md`），程序只打印它在哪里（exe 同目录 → `exe/docs` → 当前目录）。把几百行散文 `go:embed` 进去，只会让 `--help` 的输出变成一堵墙，还多出分页器、编码、终端宽度一堆麻烦。
- 内置分页器优于调用 `less`/`more`：外部 pager 在 Windows 控制台里会把 UTF-8 中文打成乱码。
- 未知选项要给**拼写建议**：`--quite` → "did you mean `--quiet`?"

## 8. 能进管道，能进脚本

- `--json` 输出 NDJSON，一行一个事件（plan / progress / done / error），`jq` 直接吃。
- 不因为输出不是终端就改变行为（除了动画）。
- `--quiet`、`--log <file>`、`--no-progress`、`--no-color` 这些开关，是为了让工具能被别的程序调用。

## 9. 尊重机器：不写系统盘，不动全局状态

这是血泪教训。我一开始想的是"改 hosts，把 LM Studio 的下载域名指到本地镜像网关"。结果是：

- 安全软件（360 主动防御）拦住了对 `hosts` 的写入；
- 一次失败的还原脚本把 `hosts` 写成了 0 字节，那台机器的域名解析全塌了；
- 即使成功，LM Studio 的**模型搜索**也会一起失效，因为它和下载共用同一个域名。

最后正确的解法反而是最朴素的：**不要碰 LM Studio，也不要碰系统**。不经过它的下载器，直接把文件按它认的目录布局放好。零权限、零全局状态、卸载就是删文件。

原则：**能用用户态解决的，绝不申请管理员权限；能写自己目录的，绝不写系统目录。**

## 10. 校验要分级，别为了安全感浪费十分钟

- 有 SHA256 就校验，但要允许"大文件首次下载跳过全量哈希"——7 GB 的哈希要几分钟，而首次下载出错的概率本来就低。
- `auto`：小文件（≤ 4 GiB）校验；续传过、重试过的校验；`--verify sha256` 强制；`--verify off` 放弃。
- 失败要**删掉坏文件**并说明原因，而不是让用户对着一个哈希不符的文件猜。

## 11. 能双击，也能脚本化

- 不带参数运行时进交互式菜单——双击 exe 的人是真实存在的用户。
- 双击打开的控制台**出错时不要立刻消失**，等一个回车。
- 菜单和命令行走**同一条代码路径**（内部把选择拼成 argv 再解析），避免"菜单能下、命令不能下"的分裂。

## 12. 速度要能被测量，而不是被宣传

- `ggufget doctor` 实测三个镜像并排序。用户网络和我写代码时的网络不是同一个网络，别写死"ModelScope 最快"。
- 测速**串行**：三个并发测速会抢同一条带宽，测出来的排名没有意义。
- 测速允许被超时截断：慢镜像本来就会被 20 秒切断，已读到的字节数就是它的真实速度。

## 13. 国际化不是翻译，是把字符串拿出来

- 所有面向用户的文本都在一个表里（`internal/i18n`），`--lang zh|en|fr|es|ru` 一行切换。
- 中英文混排的表格要按**显示宽度**对齐（CJK 占两列），否则中文界面永远是歪的。
- 报错信息也要翻译。半中半英的报错比纯英文更让人困惑。

## 14. 发布要可复现

- `make dist` 一条命令产出六个平台的二进制和 `SHA256SUMS`。
- 安装脚本校验哈希，而不是"下载后直接执行"。
- `CHANGELOG.md` 记录**为什么**改，而不只是改了什么。

## 附：一页速查表

| 维度 | 要有 |
| --- | --- |
| 安装 | 单文件 / 一条命令 / 不需要管理员 |
| 默认 | 不配置可用，配置可查看，不偷偷生成 |
| 输入 | 序号、关键词、来源 URL 都能用；歧义不猜 |
| 反馈 | 速度、ETA、连接数；非 TTY 不刷屏 |
| 中断 | 临时文件 + 续传依据 + 完成才改名 |
| 错误 | 说人话、给下一步、退出码有契约 |
| 帮助 | `--help` 总表、`help <cmd>` 细节、说书写成外置文档、选项纠错 |
| 集成 | stdout/stderr 分离、`--json`、quiet/log |
| 边界 | 不写系统目录、不要特权、卸载即删 |
| 校验 | 分级策略，失败删坏文件 |
| 体验 | 双击可用、出错停住 |
| 度量 | `doctor` 实测而不是写死结论 |

如果只能保留三条：**默认值要对**、**失败要说人话**、**不要碰系统**。
